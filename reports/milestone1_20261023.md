## 实现文件与接口

新增组件在 `src/memory_management/`：

| 文件 | 接口/职责 |
| --- | --- |
| `config.py` | `MemoryConfig`、`ManagerMode`；baseline_framesamp / fifo / random |
| `types.py` | `FrameRecord`、`MemorySlot`、`Candidate`；独立持有只读数组与原帧 ID |
| `rolling_buffer.py` | `RollingObservationBuffer`；连续流、160 帧上限、episode reset |
| `bounded_bank.py` | `BoundedMemoryBank`；32 槽、受保护锚点/近期槽、阶段配额、事务替换 |
| `packer.py` | `ManagedMemoryPacker.pack`；时间排序、padding、归一化与因果检查 |
| `online_controller.py` | `ingest / update / prepare / reset`；FIFO/随机共享流式管理路径 |
| `policy_adapter.py` | `install_memory`；仅绑定当前策略实例，保留原模型、采样及动作接口 |

`baseline_framesamp` 不修改策略、不消耗 RNG；managed 模式使用相同冻结 checkpoint。
位置编码由官方频率/空间网格按原帧 ID 生成，超出4096不会访问固定表。
不改动 vendor、原 V-A/V-B 脚本或 `validation/` 中封存代码。

四张量均为 frame-major，每帧16 token，最多32帧：

| 张量 | shape | dtype |
| --- | --- | --- |
| static_image_emb | [512, 2048] | float32 |
| static_pos_emb | [512, 768] | float32 |
| static_state_emb | [512, 8] | float32 |
| static_mask | [512] | bool |

零 padding 后才对整个 state 张量归一化一次，与官方行为一致。对相同特征/索引，
先将官方输出转换成 float32，再以 rtol=1e-6、atol=2e-7 比较；mask 精确比较。
原关节0..6、gripper7，模型 action horizon20、执行16步；实际运行 manifest 再从真实模型记录。
环境 control_freq/sim_freq 从每场真实环境读取到 `timebase.json`，不猜测示范时间戳。

## 有界存储与窗口范围

ring160 + bank32 共同最多持有192个不同 FrameRecord，逐帧数组复制避免一个视图滞留整批特征。
只保存策略需要的4x4 token、原始 state、位置；不保留完整历史 RGB 或8x8/2x2特征。
视觉编码批次最多8帧，没有随历史增长的待处理候选列表。

完整维度压力测试逐模式输入6201帧，检查 warmup、1339、3999、4097、6200等边界。
FP16/BF16图像特征 + float32位置/state 的保守常驻特征上限为22,026,240 bytes（约21 MiB）；
如视觉输出为float32，上限随每帧实际字节数调整，运行时逐决策审计。
这个口径不包括 checkpoint、模型工作区、输出张量、传输中的输入视频、JAX编译缓存及评估日志。
压力报告另记录进程 peak RSS，不将常驻特征计数等同于整个进程内存。

对 F∈{31,32,100,467,1339}，近期槽精确等于官方 FrameSamp 的最后4槽，approx=false。
超过 ring 能覆盖的跨度时使用可用同阶段帧近似，并逐决策记录 `recent_window_approx=true`。
不能宣称160帧ring可永久精确保留均匀采样窗口。长示范离开ring后仍从bank中可用同阶段帧刷新，
避免近期槽晋升造成历史槽不足；阶段槽数继续匹配当前 D0。
M1 候选只用 stride16 周期帧；真实运动事件检测与 learned 选择器属于后续 milestone。

## 2026-10-23 运行中发现并修复的问题

第一次 GPU 运行在 FIFO 的 BinFill 后、VideoUnmaskSwap 的第二个视频包处失败。
服务端日志显示官方客户端后续 `add_buffer` 包将 `exec_start_idx` 置为0；适配器把这个默认值误判为执行边界改变，导致 websocket 返回异常。该问题与 checkpoint、CUDA 或仿真环境无关。
修复提交为 `22212f0`：只有收到正的边界值时才更新/校验执行边界，后续0值沿用当前 episode 边界；新增回归测试并通过。旧失败目录保留为 `M1_acceptance_20261023_boundary_bug`，新的入口从干净目录重新执行。
