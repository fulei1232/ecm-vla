# Milestone 2：周期候选与因果事件检测

**日期：2026-10-23**  
**状态：候选生成与在线接口已实现；合成工程验收通过；真实任务 precision/recall 尚未作为正式结果报告。**

## 已完成

1. `CausalEventDetector`：由运动速度、位移、夹爪变化和可选接触信号计算显著性，并进行因果 peak 检测。
2. `CausalCandidateGenerator`：按固定步长生成周期候选，合并事件候选，生成稳定的 episode/frame/event ID。
3. 视觉过滤：使用冻结视觉特征或帧特征均值做余弦相似度去重；事件候选在视觉重复时保留，周期候选会被过滤。
4. 在线接入：`OnlineMemoryController` 支持可选候选生成器；FIFO/Random 仍使用原有固定容量、保护槽和阶段配额约束。
5. 事件元数据：`Candidate` 和 `MemorySlot` 记录 sources、event_types 和 event_ids；controller stats 输出候选队列、槽位来源和事件 ID。
6. 可复核诊断：输出逐帧 `timeline.csv`、显著性和事件峰值 SVG 图、在线记忆槽快照和 JSON 诊断结果。
7. 策略适配器：候选生成器可选地通过 `install_memory(..., candidate_generator=...)` 注入，不改变默认 M1 路径。

## 因果保证

- `observe(frame)` 只读取当前帧和已经观察的前一帧/历史分数；
- 候选的 `confirmed_at_frame` 等于或晚于候选帧；
- 不读取未来图像、未来状态、未来动作或隐藏 episode 标签；
- 同一 episode 的帧必须连续输入；跳帧和跨 episode 输入会报错；
- 事件 ID 由 `episode_id + frame_id + event_type` 确定，不依赖未来信息。

## 真实轨迹尺度诊断（annotation-only）

为检查“显著性近似恒定”的问题，使用 M1 acceptance 中 6 条真实轨迹做离线逐帧诊断。`gt` 阶段变化、demo/exec 边界和 success/fail 变化只用于离线对照，未输入在线 detector，因此该指标不是正式事件检测结果。

```bash
python3 scripts/analyze_milestone2_real_traces.py \
  --episodes-root results/M1_acceptance_20261023/episodes \
  --out results/M2_real_trace_analysis
```

固定物理尺度在 6 条轨迹合计产生 178 个峰，其中 168 个为 annotation-only 对照下的误触发，precision 为 5.6%、recall 为 45.5%。分数中位数约为 4.7，说明直接调低阈值不能解决单位/频率标定问题。

加入基于历史中位数和 MAD 的自适应尺度，并在历史窗口建立前禁止启动伪峰后，峰数降到 38 个，误触发降到 30 个，precision 提升到 21.1%；recall 为 36.4%。这证明自适应尺度能减少连续误触发，但仍不能作为正式事件性能结论，也不能替代人工事件标注。当前默认配置仍保持固定尺度；自适应尺度只作为待标定的诊断选项。

逐轨迹结果和显著性分布见 `results/M2_real_trace_analysis/analysis.json`。下一步需要先确认状态单位、采样频率和事件定义，再用人工标注或可靠任务事件标签完成正式 precision/recall、漏检和检测延迟验收。
