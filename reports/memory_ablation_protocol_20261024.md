# 记忆消融诊断：冻结策略是否使用记忆内容（2026-10-24）

状态：方案，运行前封存。只使用 val split；V-A 结果目录只读。本方案在看到任何消融结果之前写定。

## 1. 目的

Teacher Oracle 第 3 步在三个任务上都没有看到闭环收益：PatternLock +5 未达显著，BinFill 和 VideoUnmaskSwap 合并为 0（见 `teacher_oracle_step3_summary_20261024.md`）。V-A 里，删掉近期窗口（D4L）使 PatternLock 从 71.7% 跌到 23.3%，而 BinFill 和 VUS 几乎不变。

本诊断直接回答：冻结策略在每个任务上是否使用记忆内容；如果使用，是只用近期帧，还是也用长历史。结果决定记忆管理研究的后续方向（见第 6 节）。

## 2. 范围

- 任务：PatternLock、BinFill、VideoUnmaskSwap。
- episode：val 0–19；模型种子 7、8、9；共 180 组（任务 × episode × 种子）。
- checkpoint、策略配置、执行步长（16）、步数上限（1300）都与 V-A 相同。

## 3. 条件

记忆的划分沿用 V-A 和 `partition.py`：决策时刻 F 的官方 FrameSamp 选帧为 U，锚点 A = U[:1]（第 0 帧），历史 H = U[1:-4]，近期 R = U[-4:]。R 的最后一帧就是当前帧 F。

| 条件 | 记忆 | 帧数（F ≥ 31 时） |
|---|---|---|
| U0 | U，官方选帧 | 32 |
| NH | A ∪ R：去掉全部历史槽 | 5 |
| NM | 只留当前帧 F | 1 |

- 当前帧本来就是策略的当前观测，所以 NM 的记忆不提供当前观测之外的任何信息。
- 去掉的槽位按官方打包的方式右侧补齐并掩码；每个 episode 开头有效帧不足 32 个时，官方打包也是这样处理。位置编码保留各帧的原始时间。模型和打包代码都不改。
- 三个条件都不跑专家，也不打分。
- 每组的三个条件在同一个服务器进程内完成，顺序按固定种子随机；环境种子相同，每个 episode 开始时策略 RNG 都重置。

## 4. 有效性门槛

- **G3 工程错误**：错误率 ≤ 2%。
- **G5 同进程**：全部组完成，且每组的三个条件在同一个服务器进程内。
- **GA 选帧审计**：每个决策实际送入模型的帧都与第 3 节的定义一致（U0 = 官方选帧，NH = A ∪ R，NM = {F}），有效 token 数 = 16 × 帧数。

门槛未全部通过时，结果只作工程诊断。

## 5. 统计

- 对比：A1 = NH − U0，A2 = NM − U0，每个任务分别计算，共 6 项。
- 方法：按 episode 重抽样、保留同一 episode 全部种子的配对 bootstrap，20000 次（种子 20261024）；6 项一起做 Holm 校正，α = 0.05；界限 δ = 12 个百分点。
- 状态定义与 Teacher Oracle 相同：
  - 提升：95% CI 下限 > 0，且 Holm p < 0.05；
  - 退化：95% CI 上限 < 0，且 Holm p < 0.05；
  - 小于界限：90% CI 落在 (−δ, +δ) 内；
  - 未定：其他情况。

## 6. 判定规则

**阳性对照**：PatternLock 的 A2 必须是"退化"（依据 V-A 的 D4L）。否则判为"诊断无效"，先排查实现，其余任务不解读。

**BinFill 和 VUS 分别判定**：

- A1 退化：**长历史被使用**。单帧替换无效可能来自信息冗余，可以考虑多帧或结构化的干预。
- A1 小于界限且 A2 退化：**只用近期和锚点帧，长历史无关**。长历史怎么选都无关紧要。
- A2 小于界限：**看不出策略使用记忆**。不改策略，记忆管理在该任务上就没有作用空间，应考虑策略适配（Milestone P），或换用依赖记忆的任务。
- 其他：**未定**。加种子 10、11 扩展，规则不变，另立输出目录。
