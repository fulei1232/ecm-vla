# 记忆预算标定：PatternLock 在 16 帧和 8 帧下的基线（2026-10-25）

状态：方案，运行前封存。只使用 val split；V-A 结果目录只读。本方案在看到任何标定结果之前写定。

## 1. 目的

记忆消融和 Teacher Oracle 的结果表明：PatternLock 的策略强烈依赖长历史（去掉历史槽后从 66.7% 跌到 1.7%），但官方 32 帧均匀采样很密（相邻帧间隔中位数 4.5 帧），信息冗余，所以老师在 32 帧下换帧没有可见空间。

记忆预算缩小后，被丢掉的帧不再是已选帧的近邻，选哪几帧可能变得重要。本标定只测基线：在 16 帧和 8 帧均匀采样下，成功率下降多少，据此按第 5 节的规则决定是否、在哪个预算下跑老师。

## 2. 范围

- 任务：PatternLock。
- episode：val 20–49。与此前所有实验用过的 0–19 不重叠，避免按基线挑预算后，在同一批 episode 上比较老师时产生偏差。
- 模型种子 7、8、9；共 90 组。
- checkpoint、策略配置、执行步长（16）、步数上限（1300）都与 V-A 相同。

## 3. 条件

| 条件 | 记忆 | 帧数（F ≥ 31 时） |
|---|---|---|
| U0 | 官方 FrameSamp：`even_sampling_indices(F, 32)` | 32 |
| B16 | `even_sampling_indices(F, 16)` | 16 |
| B8 | `even_sampling_indices(F, 8)` | 8 |

- 三个条件都包含第 0 帧和当前帧 F，与官方采样函数相同，只是帧数不同。
- 空出的槽位按官方打包的方式右侧补齐并掩码，位置编码保留原始时间，模型和打包代码都不改。
- 不跑专家，也不打分。
- 每组的三个条件在同一个服务器进程内完成，顺序按固定种子随机；环境种子相同，每个 episode 开始时策略 RNG 都重置。

## 4. 有效性门槛

- **G3 工程错误**：错误率 ≤ 2%。
- **G5 同进程**：全部组完成，且每组的三个条件在同一个服务器进程内。
- **GA 选帧审计**：每个决策送入模型的帧都与第 3 节的定义一致，有效 token 数 = 16 × 帧数。

## 5. 选预算的规则

记 s(U0)、s(B16)、s(B8) 为各条件的成功率（点估计），下降量 d = s(U0) − s(预算)。

- 按 16 帧、8 帧的顺序，选第一个同时满足以下两条的预算：
  - d ≥ 15 个百分点（基线下降明显，选择才有发挥余地）；
  - s ≥ 20%（策略在该预算下仍然可用，没有崩溃）。
- 两个预算都不满足：不跑老师，结论写为"缩小预算没有找到适合老师检验的设置"。

另外报告 B16 − U0 和 B8 − U0 的配对 bootstrap 置信区间（按 episode 重抽样，20000 次，种子 20261024；两项做 Holm 校正），只作描述，不参与选预算。
