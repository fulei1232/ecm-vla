### 1.2 根因一：专家的关节目标是随机的（证据强，因果尚未用干预实验证实）

- `fruit_picking/solver.py` 中，reach 和 carry 两个阶段调用 `plan_qpos_to_pose`。这是 mplib 0.1.1 的实现：先从当前关节角、再从 20 个随机初值求 IK，收集所有不重复的解，然后用 RRTConnect 规划到其中任意一个。approach 和 pull 用的是确定性的直线规划 `plan_screw`。
- 10 月 30 日的分段诊断（`results/fruit_phase_diagnosis_20261030_v2/report.md`）中，只让 K0 执行某一个阶段、其余交给专家：reach 2/8，carry 4/8，approach、grasp、pull、release 都是 8/8。**失败的阶段恰好就是使用随机 IK 的两个阶段。**
- 示范数据（`data/fruit_picking/rm75b_eg2/train`，200 条）的统计：
  - reach 段和 carry 段里，各约 10% 的第 1 关节摆幅超过 2.1 rad（第 90 百分位分别为 2.11、2.12 rad）；
  - 抓取时刻（approach 段末）的 q7，539 次中有 484 次落在 [−3, −1] rad，其余约 10% 落在相差约 π 或 2π 的其他解上；
  - 训练归一化统计（`data/finetune_kf/fruit_dart_rm75b_train/assets/robomme/norm_stats.json`）里，q7 状态的 1%–99% 分位数为 −5.73 到 4.21 rad；
  - URDF 中第 7 关节的限位是 ±6.28 rad，相当于正反各一整圈。
- 策略的动作是 16 步关节增量（`DeltaActions`，相对当前状态），执行方式为 `pd_joint_pos`。同样的画面下，专家有时把腕部转好几 rad，有时完全不转，策略无从区分。
- 训练损失从 0.022 降到 0.0018，说明模型并没有欠拟合，问题出在数据本身不一致。

### 1.3 根因二：DAgger 采集与真实失败状态不重合（已确认）

依据是最新一轮的采集（`runs/fruit_dagger_full_task_20261031/collection`）和代码 `scripts/diagnose_fruit_phase_episode.py`：

- **reach 接管时策略还没动。** 接管规则是策略走满 64 步、离果实仍超过 14 cm 就接管，可策略开局本来就要发呆 77–110 步。324 次 reach 接管中，94% 的末端位移不到 5 cm（中位数 0.6 cm）。所以 409 段纠偏里的 307 段，基本是专家从起点重做了一遍正常 reach。
- **关键阶段从没交给策略。** full_collect 模式下，approach（7481 步）、pull、release、observe、settle，以及阶段切换，全部由专家执行。评测中"停在离果实 3–6 cm 处始终抓不上"的失败恰好发生在 approach，这类状态一条也没采到。
- **carry 阶段的错误被掩盖。** 策略在搬运途中下发的松爪指令被强制改为闭合，共 316 次。
- **有价值的片段被丢弃。** 策略自己完成 reach 后，专家从这个不够准的位置做的 approach 没有被导出，因为导出脚本只导出以 `*_repair` 开头的片段。
- **记忆上下文和评测不一致。** 纠偏片段只保留 32 帧历史，而评测时的记忆覆盖整个回合。
- 训练混合数据中约 66% 的样本来自这些纠偏片段。

## 5. 统一指标定义（全部由 `scripts/analyze_fruit_failure_modes.py` 计算）

记 a_t 为第 t 个控制步实际执行的 8 维动作（7 个关节加夹爪），p_t 为策略原始输出（没有安全包络时 p_t = a_t）。

| 指标 | 定义 |
|---|---|
| success / fail / timeout | 取自 `result.json` 的 outcome；fail 在本任务中基本等于掉果 |
| correct_in_basket、wrong_in_basket、first_target_in_basket | 取最后一帧 `raw_frames.jsonl` 的 gt，按目标集合计算，同 `run_fruit_dagger_dev40.py` 中的 `target_metrics` |
| never_detached | `final_detached == 0` |
| near_miss | never_detached 且整回合到目标的最小距离落在 (3, 6] cm，距离取自 `event_signal.jsonl` |
| wrist_over_limit | 任一步 \|a_t[6]\| > 6.28 |
| wrist_deviation（执行值 / 原始输出分别统计） | 任一步 \|a_t[6] − q7_c\| > 3 rad（原始输出用 p_t）。q7_c 为当前专家版本训练示范在 approach 段末 q7 的中位数，旧专家为 −1.56 |
| deviation_onset_context | 第一次发生偏离之前 32 步的状态，归为四类之一：正在搬运果实（有已脱离且未入篮的果实距 TCP < 4 cm）、夹爪闭合但无果实、夹爪张开且已放下至少一颗、夹爪张开且尚未摘下第一颗 |
| start_idle | 第一个满足 max_j \|a_t[j] − a_{t−1}[j]\| > 0.005 rad（j 为 7 个手臂关节）的步数 |
| freeze_200 | 第 60 步之后，连续不满足上述运动条件的最长段超过 200 步；另单独统计"已放下至少一颗且未成功"子集中的比例 |
| guard_clip_rate | 安全包络开启时，被裁剪的步数占比，逐关节统计 |
| count_exact（FruitCount） | 结束时入篮数恰好等于 N |

## 7. 已知的坑

- **pickle 兼容性：** 训练环境是 NumPy 1，系统 Python 是 NumPy 2。任何要被训练读取的 pickle 都必须用 `POLICY_PYTHON` 写出。
- **环境变量：** 构建数据集需要设置 `OPENPI_DATA_HOME`；仿真客户端需要 `VK_ICD_FILENAMES`，而且 Codex 沙箱里看不到 NVIDIA/Vulkan，仿真必须在沙箱外运行。
- **归一化统计：** 统计脚本默认批大小为 128，数据量很小时会报错，需要按数据量调小。
- **执行步长：** 官方评测循环把执行步长写死为 `obs_horizon`，`diagnose_fruit_episode.py` 中还有断言，改动时不能误改记忆的观测长度。
- **轨迹不可完全复现：** 同一布局在不同推理服务之间轨迹会不同，配对比较要尽量在同一服务会话中运行，并在报告中说明。
- **生成器的布局依赖专家：** 专家失败时生成器会换种子重试，所以布局集合依赖于专家版本。这就是新划分在阶段 0 用当前生成器生成并冻结、之后不再重新生成的原因。
- **规划失败：** mplib 规划失败会抛出 `PlanningFailure`。上一轮采集中 128 条里有 11 条因此失败，新专家要报告这个比例。
- **显存：** 一张 48GB 卡上不要同时加载超过 2 个推理服务。

## 9. 修订 1：G0 决策与阶段 2、3 的补充要求（2026-11-02）

依据：D1 报告 `reports/lowlevel_rescue_D1_20261102.md`（提交 fec9244），以及指挥者对 `results/fruit_exec_guard_dev_20261102_v2` 的复核。

### 9.1 决策

1. **G0 未通过，批准进入阶段 2。**
2. **后续平台设置采用 A0（不开安全包络，执行步长 16），不采用 A1。** 安全包络 v1 作废，原因如下：
   - **限速规格有误，责任在本文 §4.1 的写法。** v1 的 v_max 取自相邻实测状态之差，可包络约束的是"目标值 − 实测值"。由于 PD 跟踪滞后，后者大得多：专家示范中 |joint_action − joint_state| 的第 99 百分位为 0.11–0.26 rad，而 v_max 只有 0.08–0.17 rad。拿专家自己的动作去过 v1，也有 24.5% 的控制步会被裁剪（逐关节：关节 1 为 12.3%，关节 7 为 4.6%）。所以 A1 中 47% 的步被裁剪，主要是在限制正常动作，A1 的结果不能用来回答"防住腕部失控有没有用"。
   - **q7 ∈ [−π, π] 挡不住换解。** 执行值的腕部偏离只从 24/40 降到 22/40。
   - **包络交集为空时会产生工程失败。**
3. **执行步长保持 16，不再测试更短的步长。** A2–A4 失败的机制已经确认（见 9.2），与实现无关。
4. 阶段 1 的 8/200 个工程失败按报告原样保留，不需要再处理。

### 9.2 新确认的问题：静止段让策略"永远晚一步开始"

- **现象。** 在起始位姿附近的早期决策中（每条 episode 取前 12 个，每个条件共 480 个动作块），A0 预测的动作块在第 8 步的位移中位数为 0.004 rad，到第 20 步为 0.101 rad。也就是说，策略总是预测"先停约 8 步再走"。执行 16 步时还能走到"走"的部分，执行 8 步或 4 步时每次都只执行了"停"的那段。例如 A4 的 FruitOccludedRipe ep211 和 FruitCount ep203，机器人整整 1100 多步都停在起点附近（距目标始终约 0.45–0.56 m）。
- **原因。** 专家示范开头有 30 步完全静止的 observe 段。在这段时间里画面不变，策略无法判断自己处在第几步。监督样本中，"若干步静止 + 后续开始 reach"的动作块占了大头，于是策略学到的是"动作在后面才开始"。放果后的 settle 段（12 步）和 done 段（5 步）同样是完全静止的。这很可能就是"开局发呆约 78 步（示范为 30 步）"和"放下后冻结"的直接机制。这一条属于推断，要在阶段 3 用数据改动来验证。
- **指标缺陷。** D1 中 A2–A4 的 `start_idle` 中位数为 41–48 步，但机器人其实没离开起点，因为微小抖动就超过了 0.005 rad 的阈值。这个指标需要补充（见 9.5）。

### 9.3 对阶段 2 的补充（专家改造的范围不变）

1. 不改动专家和环境中的 `OBSERVE_STEPS`、`SETTLE_STEPS`、`CLOSE_STEPS`、`OPEN_STEPS`，静止段在阶段 3 的数据构建中处理。

**计数任务 v2（事件记忆）：**

- 取消"入篮数恰好等于 N 即结束"。回合在以下任一情况结束：
  - 策略发出"完成"信号：回到 rest 附近、夹爪张开、没有持果，并保持静止至少 40 步，具体阈值在设计说明中给出；
  - 达到预算；
  - 入篮数超过 N（立即判失败）；

2. **漏洞：可以提前开工。** 这是修订 8 留下的：灯亮前离开 rest 不判失败。策略可以无视红灯、在第 31 步直接开工，再按绝对步数停下，完全不需要记忆。本轮回放的 `early_start` 都是 0，但规则必须补上，见 17.3。
3. **事件信号定为 `any_hanging`（按 §15.4 第 6 项由我决定）。**
   - 原 `mature` 信号只在靠近成熟果时触发。专家只摘成熟果，所以示范数据上两个版本的事件区间完全相同（遮挡 127 次，计数 180 次）。

   - 之后所有条件的数据构建和推理一律使用 `any_hanging`。
4. **关键发现：现有设计下，事件记忆在计数任务上不可能胜过均匀记忆。** 我在 50 条计数专家回放上做了离线“记忆信息可得性”审计。
   - 方法：调用 `event_keyframes.select`，在结束决策时刻（`completed_releases == N`）检查每次采摘的证据区间里有没有至少一个被选中的帧。证据区间指从包含脱果步的近场区间起点，到该位置补果的那一步。

   - 原因：证据区间约 84 ± 9 步，而 K0 在决策时刻的均匀帧间距约 61 步，几乎每次采摘都会被拍到；K4/K8 只保留最近 2 个或 4 个事件，还占掉了均匀帧位。
   - 我按实测节奏模拟了更大的 N（N≤5 与实测吻合）：

     | N | K0 | K8 | 每个事件留一帧、最多保留 12 个事件 |
     |---|---|---|---|
     | 5 | 0.85 | 0.49 | 1.00 |
     | 6 | 0.68 | 0.32 | 1.00 |
     | 8 | 0.20 | 0.00 | 1.00 |
     | 10 | 0.00 | 0.00 | 1.00 |

   - 结论：事件记忆要有优势，需要同时满足两点：保留**全部**事件，而不是最近几个；采摘次数要多到均匀采样覆盖不过来。
5. **时钟问题。**
   - 模型的记忆帧用绝对步号做时间编码（见 16.1 第 3 条），所以“开工时刻 + 节奏”这条路对 K0 是开着的：均匀帧能看到灯从红变绿，开工时刻可以定位到约 ±50 步以内，而专家节奏很规律（每颗间隔标准差约 15 步）。N=8 时估计仍有约八成成功率（iv-o 在 N 2–5 上实测为 45/50）。训练出的 K0 可能学到“开工后过 a + b·N 步就停”，而不去数事件。

### 20.4 变更二：DART 配方（两个任务都适用）

1. **同一回合的重试固定 N 和布局。**
   - DART 回合的几何和 N 都用 attempt 0 的种子（4100000 + 16 × episode），重试只换噪声种子和被扰动的周期；
   - 噪声种子由 (episode, attempt) 确定，写进记录。
2. **只扰动 2 个采摘周期。**
   - 每个 DART 尝试从本回合的采摘周期中均匀随机选 min(2, 目标数) 个；
   - 一个周期指：从离开 rest 或篮子、前往第 k 个目标开始，到第 k 次释放为止；
   - 被选中的周期内按原配方加扰动：OU，σ = 0.04 rad，τ = 10；reach、pull、carry 全幅，approach 半幅，其余阶段关闭；每个被选中的周期开始时，OU 状态从 0 起步；
   - 其余周期不加噪声。
   - 遮挡任务的目标数是 2–3，所以这一改动对它影响很小，为统一起见同样执行。
3. **clean 示范不变。** 重试仍按原规则换种子；clean 失败率约 1%，影响可以忽略。
4. **重试上限。** 每个 DART 回合最多 16 次尝试；若有回合 16 次都失败，停下汇报，不跳过。
5. **报告：**
   - DART 的逐尝试成功率，按任务和 N 分组；
   - 失败类型；
   - 掉果发生在第几个周期、是否为被扰动的周期；
   - 被扰动帧在 DART 数据中的占比；
   - 最终 DART 示范的 N 分布，应与 clean 示范一致。
